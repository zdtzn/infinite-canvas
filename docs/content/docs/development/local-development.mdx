# 本地开发

## 环境要求

- Bun 1.3 或更高版本。
- Docker Desktop 或 Docker Engine，用于验证完整服务端模式。
- Git。

## 获取源码

```bash
git clone https://github.com/zdtzn/infinite-canvas.git
cd infinite-canvas
```

## 前端开发模式

```bash
cd web
bun install
bun run dev
```

默认地址为 `http://localhost:3000`。Vite 开发模式下 `PUBLIC_MODE=false`，数据、素材和个人渠道保存在浏览器本地，适合页面与画布交互开发。

它不会完整覆盖以下正式能力：

- 登录与成员隔离。
- SQLite 持久化和迁移。
- 管理员共享渠道与 API Key 加密。
- 服务端任务队列、额度事务和修为结算。
- 跨设备项目、藏卷阁和生成历史恢复。

## 完整单体模式

验证生产链路时，在仓库根目录运行：

```bash
docker compose -f docker-compose.local.yml up -d --build
docker compose -f docker-compose.local.yml ps
curl http://127.0.0.1:3000/health
```

该模式会构建前端并由 Bun 服务端统一提供页面和 `/api/*`，数据写入 `infinite-canvas-data` Docker 卷。

停止容器：

```bash
docker compose -f docker-compose.local.yml down
```

不要附加 `-v`，否则会删除本地测试数据卷。

## 代码检查

在 `web/` 目录运行：

```bash
bun run typecheck
bun run test
bun run format:check
bun run build
```

`typecheck` 同时检查前端和 `server/`；`test` 同时运行服务端与前端测试。

## 文档站

```bash
cd docs
bun install
bun run dev
```

提交文档前运行：

```bash
bun run types:check
bun run build
```

## 数据目录

容器内默认数据目录为 `/data`。本地直接运行服务端时可通过 `DATA_DIR` 和 `WEB_ROOT` 覆盖，但团队开发与验收建议使用 Docker，避免不同系统上的路径和权限差异。

主要环境变量见仓库根目录 `.env.example`。`APP_ENCRYPTION_KEY` 一旦用于保存渠道密钥就应保持稳定，不要把真实密钥提交到 Git。
