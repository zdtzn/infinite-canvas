# 漏洞提交

安全策略英文原文见 [SECURITY.md](https://github.com/zdtzn/infinite-canvas/blob/main/SECURITY.md)。

请不要在公开 Issue 中发布漏洞细节、利用代码、API Key、真实用户数据或未脱敏截图。

## 提交流程

1. 优先使用 GitHub Private Vulnerability Reporting 或创建草稿 Security Advisory。
2. 如果仓库暂未开放私密报告入口，只创建一个不含技术细节的公开 Issue，请求维护者提供私密联系方式。
3. 在转入私密渠道后再提供完整复现信息。

建议包含：

- 受影响的版本、提交或镜像摘要。
- 部署方式和必要环境变量状态。
- 清晰的复现步骤和攻击前提。
- 对其他用户、渠道密钥、额度或数据完整性的影响。
- 已脱敏的日志、截图或 PoC。

## 优先关注范围

- 登录、会话 Cookie、账号停用和管理员权限绕过。
- 跨用户访问项目、藏卷阁、生成历史、任务、头像或修炼数据。
- 平台 API Key 解密、泄露或进入前端与日志。
- 生图额度绕过、重复扣除、重复返还或重复奖励修为。
- SSRF、上游重定向绕过、提示词图片代理和任意远程脚本执行。
- 文件上传、路径穿越、导入导出、存储配额和未授权文件访问。
- SQLite 迁移、备份恢复或浏览器缓存导致的数据串号。

## 运行模式说明

正式 Docker 模式使用 Bun、SQLite、服务端加密渠道和按用户隔离的数据 API。直接运行 Vite 的本地前端模式会把个人数据与用户自行填写的接口配置保存在浏览器中，只适合可信的个人开发环境。

公网模式不允许普通用户运行任意提示词来源脚本或远程节点插件。本地模式中，用户明确安装的插件会在页面上下文执行，因此只应安装可信来源。

第三方模型服务、托管平台、浏览器扩展、用户自行泄露的密钥、无实际利用路径的安全头建议以及纯社工问题通常不属于本仓库漏洞范围。
