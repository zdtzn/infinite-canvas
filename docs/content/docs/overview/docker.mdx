# Docker 部署

主镜像包含 Bun 单体服务和构建后的前端。登录、SQLite、素材、任务、项目与提示词缓存都由同一个容器管理，持久化目录为 `/data`。

## 首次部署

```bash
git clone https://github.com/zdtzn/infinite-canvas.git
cd infinite-canvas
cp .env.example .env
docker compose up -d app
docker compose ps
curl http://127.0.0.1:3000/health
```

健康检查返回 `{"status":"ok"}` 后，可在服务器本机访问。域名尚未就绪、确需通过公网 IP 临时测试时，在 `.env` 中设置 `APP_BIND_ADDRESS=0.0.0.0`，同时保持 `PUBLIC_BASE_URL` 为空、`TRUST_PROXY=0`、`FORCE_SECURE_COOKIES=0`，并临时开放云防火墙的 `3000` 端口。测试结束后立即恢复为 `127.0.0.1` 并关闭该端口。

`.env` 至少需要确认以下配置：

```dotenv
IMAGE_REPOSITORY=ghcr.io/zdtzn/infinite-canvas
IMAGE_TAG=latest
APP_ENCRYPTION_KEY=replace-with-a-long-random-secret
JOB_CONCURRENCY=2
DATA_VOLUME_NAME=infinite-canvas-data
```

生成加密密钥：

```bash
openssl rand -base64 32
```

`APP_ENCRYPTION_KEY` 用于加密渠道密钥。首次正式使用后必须保持不变；需要轮换时，将旧密钥临时放入 `APP_ENCRYPTION_KEY_PREVIOUS`。

提示词优化由服务端统一选择文本模型，普通用户不需要也不能在浏览器中指定。管理员先在渠道配置中保存带 `text` 能力的模型，再按需在 `.env` 固定专用目标：

```dotenv
PROMPT_OPTIMIZE_CHANNEL_ID=your-channel-id
PROMPT_OPTIMIZE_MODEL=your-text-model
```

两项留空时，服务端会按管理员设置的渠道顺序使用第一个文本模型。提示词优化调用不进入修炼额度结算，只有正式生图任务消耗额度。修改环境变量后需要重建应用容器使其生效。

首次管理员账号应在只启动 `app`、尚未开放 Caddy 时通过服务器回环地址初始化，避免未配置站点被公网用户抢先注册。完整命令见 `docs/SECURE_PUBLIC_DEPLOYMENT.md`。受邀成员完成首次登录后，将 `ALLOW_NEW_USERS` 改为 `0` 并重建应用容器；已有成员仍可正常登录。

## 更新与回滚

临时本机测试可继续使用 `IMAGE_REPOSITORY` 与 `IMAGE_TAG`。正式环境必须在 `.env` 中把 `IMAGE_REF` 设置为已通过 CI 的版本标签或不可变镜像摘要，然后使用生产 Compose 覆盖：

```bash
docker compose -f docker-compose.yml -f docker-compose.production.yml pull
docker compose \
  --profile https \
  -f docker-compose.yml \
  -f docker-compose.production.yml \
  up -d
docker compose ps
docker compose logs --tail=50 app
```

需要回滚时把 `IMAGE_REF` 改回上一个已验证版本，再执行同一组命令。应用容器默认带有禁用 Watchtower 的标签，更新应在备份和验收后手动执行。

## 数据与数据卷

Compose 默认将 `infinite-canvas-data` 挂载到 `/data`。其中主要包含：

| 路径 | 内容 |
| --- | --- |
| `/data/app.sqlite` | 用户、渠道、修炼、项目、任务和流水 |
| `/data/assets` | 用户素材与头像 |
| `/data/job-files` | 生图任务结果 |
| `/data/job-references` | 生图参考图 |
| `/data/prompt-cache` | 提示词图片缓存 |
| `/data/backups` | SQLite 一致性快照 |

更新或重建容器不会删除数据卷。不要使用 `docker compose down -v`，除非明确要删除全部数据。

查看实际数据卷名称：

```bash
docker inspect -f '{{range .Mounts}}{{if eq .Destination "/data"}}{{.Name}}{{end}}{{end}}' infinite-canvas
```

## 自动备份

服务使用 SQLite 原生 `VACUUM INTO` 创建一致性快照，并对新快照执行完整性检查。默认启动 60 秒后生成第一份，之后每 24 小时运行一次，保留最近 14 份。

```dotenv
BACKUP_ENABLED=1
BACKUP_INTERVAL_HOURS=24
BACKUP_RETENTION_COUNT=14
BACKUP_DIR=/data/backups
```

管理员可在「掌教殿 > 用量」查看最近备份时间、大小和错误状态。默认备份与主库位于同一个数据卷，可防误操作和单库损坏；如需防整块磁盘故障，还应定期将备份复制到另一台机器或对象存储。

创建一份一致的完整数据卷备份到宿主机。脚本会短暂停止应用，归档 SQLite、素材、任务文件与参考图，生成 SHA-256 校验文件后再恢复运行：

```bash
BACKUP_ROOT=/root/infinite-canvas-backups \
DATA_VOLUME_NAME=infinite-canvas-data \
sh ops/backup-volume.sh
```

Compose 通过 `DATA_VOLUME_NAME` 显式固定卷名，默认就是 `infinite-canvas-data`。修改过该变量时，备份和恢复脚本必须传入同一个值。

## 恢复 SQLite 快照

先列出可用快照：

```bash
docker exec infinite-canvas sh -c 'ls -lh /data/backups'
```

选择确认过的快照后执行：

```bash
DATA_VOLUME="$(docker inspect -f '{{range .Mounts}}{{if eq .Destination "/data"}}{{.Name}}{{end}}{{end}}' infinite-canvas)"
IMAGE_REF="ghcr.io/zdtzn/infinite-canvas@sha256:替换为已验证的镜像摘要"
SNAPSHOT="app-YYYYMMDDTHHMMSSZ-0000000000000.sqlite"

docker stop infinite-canvas
docker cp infinite-canvas:/data/app.sqlite "./app.sqlite.before-restore"

docker run --rm --user root --entrypoint sh \
  -v "$DATA_VOLUME:/data" \
  "$IMAGE_REF" \
  -c "cp '/data/backups/$SNAPSHOT' /data/app.sqlite && rm -f /data/app.sqlite-wal /data/app.sqlite-shm && chown bun:bun /data/app.sqlite"

docker start infinite-canvas
sleep 10
docker inspect -f '{{.State.Health.Status}}' infinite-canvas
docker logs --tail=50 infinite-canvas
```

恢复时必须停止应用，并删除旧库对应的 `-wal`、`-shm` 文件，避免把恢复前的写入重新合并进快照。SQLite 快照不包含素材和任务文件；需要恢复完整数据卷时，应使用带校验和与恢复前安全备份的 `ops/restore-volume.sh`。

## HTTPS 与域名

先将域名 A 记录解析到服务器公网 IP，并在云安全组和系统防火墙开放 TCP `80`、`443`；HTTP/3 可额外开放 UDP `443`。不要把数据库目录或 Docker Socket 暴露到公网。

例如域名为 `mingche.click`：

```dotenv
DOMAIN=mingche.click
PUBLIC_BASE_URL=https://mingche.click
APP_ENCRYPTION_KEY=你的固定加密密钥
```

启动 Caddy：

```bash
docker compose \
  --profile https \
  -f docker-compose.yml \
  -f docker-compose.production.yml \
  up -d
docker compose ps
docker compose logs --tail=50 caddy
curl -I https://mingche.click/health
```

Caddy 会自动申请并续期 TLS 证书。启用 HTTPS 后，应用会使用安全 Cookie，并要求配置 `APP_ENCRYPTION_KEY`。公网只需要开放 `80/443`；确认域名访问正常后，可在云安全组关闭公网 `3000` 端口。

## 本地构建

需要验证当前源码而不是发布镜像时：

```bash
docker compose -f docker-compose.local.yml up -d --build
```

文档站位于 `docs/`，使用独立镜像和 Compose 文件，不包含在主应用容器中。

## 统计分析（可选）

默认不加载统计脚本。只在自己的部署中按需设置：

```dotenv
ANALYTICS_GA4_ID=
ANALYTICS_BAIDU_ID=
```

单页路由切换会向已启用的平台上报 pageview。不要将真实统计 ID 提交到公共仓库。
